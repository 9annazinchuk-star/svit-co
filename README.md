# Svit&Co — двомовний сайт ремонтної компанії для Render

Готовий Node.js-сайт для майстра або команди з ремонту квартир. Публічна частина працює українською та англійською, а захищена адмін-панель дозволяє змінювати контакти, завантажувати головне фото, додавати проєкти й переглядати заявки.

## Що вже реалізовано

- маршрути `/uk` і `/en`, перемикач `EN | UA` у правому верхньому куті;
- адаптивний Liquid Glass / iOS 2026 інтерфейс без горизонтального скролу;
- послуги, портфоліо з фільтрами, модальні галереї, процес, FAQ і контакти;
- форма заявки, яка зберігається на сервері незалежно від WhatsApp;
- вибір WhatsApp, телефону, email, Telegram, Viber, Messenger або SMS — показуються тільки налаштовані канали;
- завантаження до 5 фото разом із заявкою;
- адмін-панель `/admin`: контакти, двомовний опис, SEO, головне фото, проєкти, фотографії, публікація/приховування, заявки, статуси та CSV-експорт;
- фірмовий логотип Svit&Co у шапці, footer та адмін-панелі з можливістю безпечно замінити або відновити його;
- постійне сховище Render Disk для JSON-бази та фотографій;
- безпечні заголовки, перевірка типу й розміру файлів, rate limiting і honeypot;
- `robots.txt`, `sitemap.xml`, favicon, локалізовані title/description;
- Docker не потрібен.

### Файли бренду

- `public/assets/logo-svitco.png` — основний PNG із прозорістю;
- `public/assets/logo-svitco.webp` — оптимізована WebP-версія;
- `public/assets/logo-svitco-light.png` — версія для темних поверхонь;
- `public/favicon.svg` і `public/assets/favicon-32x32.png` — іконки браузера;
- `public/assets/apple-touch-icon.png` — іконка для iPhone/iPad.

Логотип можна замінити в `/admin` у розділі **Налаштування → Логотип Svit&Co**. Завантажений файл зберігається на Persistent Disk у `${DATA_DIR}/uploads/` і не зникає після повторного deployment. Кнопка **Відновити стандартний** повертає логотип із комплекту сайту.

### Ілюстративні фотографії

- `public/assets/photos/hero-renovation.webp` — головне фото оновленої вітальні;
- `public/assets/photos/bathroom-renovation.webp` — фото для послуги ремонту ванної;
- `public/assets/photos/kitchen-renovation.webp` — фото для кухні та внутрішнього оздоблення.

Фотографії оптимізовані у WebP, мають задані пропорції та не спричиняють стрибків макета під час завантаження. Це нейтральні ілюстрації послуг, а не твердження про виконані Svit&Co замовлення. Реальні об’єкти власник додає через `/admin`; вони автоматично з’являються в портфоліо.

Поки реальні проєкти ще не завантажені, у портфоліо показуються три короткі картки з напрямами робіт: комплексне оновлення квартири, ванна кімната та кухня. Кожна картка має явну позначку **«Ілюстративний приклад»**. Після додавання першого реального проєкту через адмін-панель демонстраційні картки автоматично приховуються.

## Локальний запуск

Потрібен Node.js 20 або новіший.

```bash
npm install
cp .env.example .env
npm start
```

Відкрийте:

- сайт: `http://localhost:3000/uk`
- English: `http://localhost:3000/en`
- адмін-панель: `http://localhost:3000/admin`

Для локального запуску без `.env` тимчасовий пароль адміністратора — `change-me-now`. Не використовуйте його на опублікованому сайті.

## Завантаження на GitHub

1. Розпакуйте ZIP.
2. Створіть порожній репозиторій на GitHub.
3. У папці проєкту виконайте:

```bash
git init
git add .
git commit -m "Initial renovation website"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Файл `.env` не завантажується в GitHub завдяки `.gitignore`.

## Розгортання на Render

### Варіант A — через `render.yaml` (рекомендовано)

1. У Render відкрийте **New → Blueprint**.
2. Підключіть GitHub-репозиторій.
3. Render прочитає `render.yaml` і створить Web Service та Persistent Disk.
4. Заповніть секретні змінні:
   - `ADMIN_PASSWORD` — довгий унікальний пароль;
   - `BASE_URL` — повна адреса сервісу, наприклад `https://svitco-renovation.onrender.com`.
5. `SESSION_SECRET` буде згенеровано автоматично.
6. Запустіть deployment.

У `render.yaml` використано план із підтримкою Persistent Disk. Якщо у вашому обліковому записі назва плану відрізняється, виберіть доступний платний Web Service і додайте диск вручну.

### Варіант B — вручну

- Runtime: `Node`
- Build Command: `npm ci`
- Start Command: `npm start`
- Health Check Path: `/api/health`
- Disk Mount Path: `/var/data`
- Environment:
  - `NODE_ENV=production`
  - `DATA_DIR=/var/data`
  - `ADMIN_PASSWORD=...`
  - `SESSION_SECRET=...`
  - `BASE_URL=https://your-service.onrender.com`

Без Persistent Disk завантажені фотографії та заявки можуть зникнути після повторного deployment. Тому диск обов’язковий для цієї версії.

## Що заповнити перед публікацією

Після першого запуску відкрийте `/admin` і замініть:

- за потреби відкоригуйте назву `Svit&Co`;
- `OWNER NAME` на ім’я майстра;
- `CITY`, `SERVICE AREA`, `COUNTRY`, `WORKING HOURS`;
- телефон, WhatsApp та email;
- за потреби Telegram, Viber, Messenger і SMS;
- український і англійський опис;
- SEO title та description;
- головне фото й фотографії реальних проєктів.

Також адаптуйте Privacy Policy і Terms of Service під країну ведення бізнесу. Сайт навмисно не містить вигаданих відгуків, цін, сертифікатів або років досвіду; стартові фотографії інтер’єрів чітко використовуються лише як тематичні ілюстрації.

## Дані та резервні копії

- база: `${DATA_DIR}/database.json`;
- фото: `${DATA_DIR}/uploads/`;
- CSV заявок: кнопка **Експорт CSV** в адмін-панелі.

Для резервної копії завантажте `database.json` і папку `uploads` із Persistent Disk через доступний вам серверний інструмент або перенесіть проєкт на зовнішню базу/object storage перед масштабуванням на кілька інстансів.

## Важливе обмеження

Файлова JSON-база оптимальна для одного інстансу невеликого бізнес-сайту. Для кількох паралельних інстансів або великого потоку заявок перейдіть на PostgreSQL і object storage (наприклад, Supabase або S3-сумісний сервіс).
